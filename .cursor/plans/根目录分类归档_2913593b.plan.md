# 根目录分类归档与验证计划

## 已选范围与安全边界

- 采用“分层整理 + 根目录及直接关联项”：只整理根文件及其 CI、测试、脚本、文档和索引引用。
- 保留工具要求位于根目录的 `VERSION`、`UPSTREAM_COMPONENTS.yaml`、`pnpm-*.yaml`、锁文件、TypeScript/Python 配置、`.importlinter*`、README/AGENTS/CHANGELOG/BACKLOG 等入口。
- 不清理 `scratch/`、`data/`、`.artifacts/`、`artifacts/`、`.cursor/plans/`、第三方 Agent 状态、`.env` 或 `secrets/`；不改 Domain/API/Schema，不改依赖版本。
- 不修改 [FRAMEWORK_MANIFEST.json](../../FRAMEWORK_MANIFEST.json) 或 [.cursor/releases/RELEASE_EVIDENCE.json](../../.cursor/releases/RELEASE_EVIDENCE.json)；它们只由显式发布流程生成。本任务不 commit、不 push。

## 1. 固化根目录归档规则

- 新建 [docs/operations/REPOSITORY_HYGIENE.md](../../docs/operations/REPOSITORY_HYGIENE.md)，记录四类资产：必须留根、归入专责目录、可再生可删、受保护本地状态，并把入口加入 [docs/INDEX.md](../../docs/INDEX.md)。
- 先新增 [tests/tooling/test_repository_root_layout.py](../../tests/tooling/test_repository_root_layout.py)：断言根目录 YAML/YML 只保留 `UPSTREAM_COMPONENTS.yaml`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`，并断言专责 Compose 目录包含预期四个文件、根目录不再出现 `docker-compose.*.yml`。
- 该门禁只约束工程资产布局，不检查或删除凭据、运行数据和用户本地历史。

## 2. 将活跃 Compose 配置归入基础设施目录

- 新建 [infra/compose/README.md](../../infra/compose/README.md)，说明每个栈的职责、旧路径到新路径的迁移映射、从仓库根运行的命令和不带 `-v` 的安全清理方式。
- 执行语义化重命名：
  - `docker-compose.m14.yml` → [infra/compose/postgres-test.yaml](../../infra/compose/postgres-test.yaml)
  - `docker-compose.m15.yml` → [infra/compose/otel-evidence.yaml](../../infra/compose/otel-evidence.yaml)
  - `docker-compose.personal.yml` → [infra/compose/personal-production.yaml](../../infra/compose/personal-production.yaml)
  - `docker-compose.research.yml` → [infra/compose/research-validation.yaml](../../infra/compose/research-validation.yaml)
- 保持四个栈分离，不合并个人生产、完整验证和 CI 证据职责；服务、端口、网络、只读文件系统、capability drop、凭据隔离和固定镜像语义不变。
- 所有调用统一从仓库根使用 `docker compose --project-directory . -f infra/compose/...`。这是为了在文件移动后仍以仓库根解析 build context、bind mount 和根 `.env`，避免相对路径或凭据加载回归。

## 4. 精确删除可再生根目录垃圾

- 在再次确认被 `.gitignore` 忽略且无源码/文档引用后，按精确路径删除：`m0_profile_run.log`、`m13_gate.log`、`m13_reauth_gates.log`、`.vite-e2e.log`。

## 5. 分层验证与验收

1. 运行新增根布局测试和受影响的 Compose/文档测试；Python 一律使用 `uv run --frozen --no-sync python -B ...`，并设置 UTF-8 环境变量。
2. 对四个新 Compose 文件及 PostgreSQL+Collector 叠加配置逐一执行 `config --quiet`；仅使用非秘密 canary 环境值，不输出展开后的配置。
3. 以独立项目名顺序启动质量证据栈与完整 research validation 栈，执行健康检查及 PostgreSQL/Collector/Distributed/Research Compose 定向套件；结束后执行 `down`，明确不使用 `down -v`，不删除卷或业务数据。
4. 运行文档一致性、`system-spec-check`、`governance-check`，随后串行运行完整 `m0` profile：`uv run --frozen --no-sync python -B .cursor/skills/cursor-framework-check/scripts/run_all_checks.py --profile m0 --keep-going`。
5. 最终复核根 YAML 清单、旧路径剩余命中（只允许历史记录与发布快照中的说明）、ignored 垃圾清理结果、`git status --short` 和差异白名单。

验收标准：根目录不再含四个 Compose 文件和四个日志；三份必须留根的 YAML 保持原位；所有活跃命令使用新路径且 Compose 实际可解析/启动；安全拓扑与凭据边界未变化；文档索引、定向测试、两个契约 validator 和完整 M0 profile 全部通过。任何失败均保留现场、停止扩大清理范围，并报告阻塞项。
