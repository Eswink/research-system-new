## 警告（W）

- **W-1｜本复检由实施方在同一 cycle 内写出，与 EC-05 的独立两树复检**不同源**。**
  第六节的 m0 / 定向计数是**实施方实跑**留下的日志；独立结论以 cycle 3 的两树复检为准。
- **W-2｜AC-3 的禁止面是**词表**（21 条，只增不减）。** 未列入词表的新措辞（例如
  「已完成最小化授权」）**不会被**判据抓住 ⇒ 词表是**下限**不是上限；新增措辞要连带加条目 + 一条按压。
  同理 **AC-1 的文档集合是写死的四元组**：将来新增第五份"对外语义"文档时**必须**手工加入。
- **W-3｜同源句现在有 **5** 处副本**（四份文档 + 判据常量）。这是**有意**的（"同源"因此可机械判），
  但改口径必须**五处同改** ⇒ 改一处即红，是有意的摩擦，不是缺陷。
- **W-4｜AC-2 的观察窗是**锚点后 1200 字**。** 若某份文档在锚点后**插入大段合法内容**，
  必需措辞可能被挤出窗口 ⇒ **假红**（不是假绿）。修法是调整窗口或把锚点移到该节内 ——
  窗口**不得**改成"全文搜索"（那会让"这一节里声明了"退化成"文档里某处提过"）。
- **W-5｜P6 是"期望不红"的按压。** 读"14/14 按压"时必须读那张表：
  **13 条判红 + 1 条证明豁免工作**；把 14 读成"14 条都判红"是误读。
- **W-6｜新判据 437/450 行，余量 13 行。** 再扩按压或词表就要先压缩；**不得**为放内容而抬高阈值。
- **W-7｜部署面仍未验证（承 `R-D1` 口径）。** 本轮文档**如实写**"反代 / TLS / 多副本下的认证行为未验证"，
  但**没有**任何实测面 ⇒ 该条是**已知空白**，不是"已覆盖"。
- **W-8｜`apps/web/**` 本轮零改动** ⇒ 前端仍**没有**任何 token 输入面：认证开启时
  浏览器侧写操作需要外部工具或自定义 header 注入。这是"只保护写面"判词的**预期代价**，
  但**必须**在有人对前端提"为什么写不了"时有据可查（runbook §2.1 已写明两条设置形态）。
