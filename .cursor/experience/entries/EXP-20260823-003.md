# CURSOR_ERROR 瞬时失败跨会话：重试一次或改替代路径，不当作命令失败诊断

## Problem

- 现象：本会话 84 次工具失败全部为 `CURSOR_ERROR`（Read/Shell，duration <2ms，瞬时）；跨会话统计有 4 个 ≥2 次签名，其中 2 个确为跨会话：`d42fb89b03dfc2000b49`（Read，8/22 两个会话）、`f3eb42211d52fea83bd0`（Shell，8/22 与 8/23）。另有 `e3b0c44298fc1c149afb`（TOOL_FAILURE ×6，tool_name/duration 全 null，为 sha256("") 前缀的空载荷哨兵，单文件跨两天）。
- 上下文：Windows + hook 文本扫描边界；与 LEARN-20260822-001（Read 9710fd0…）同族。
- 影响：失败签名内容相关（同文件同内容→同签名），单会话内签名几乎不重复，靠跨会话聚合才能发现；空载荷哨兵会污染统计（无上下文，不可诊断）。

## Solution

- 根因：hook 对 Read/Shell 载荷的文本扫描在中文/引号/BOM 边界偶发瞬时拒绝（duration <2ms 的 fail-closed），非命令本身失败；空载荷 TOOL_FAILURE 是蒸馏/记录层的哨兵事件，无工具上下文。
- 解法（稳定模式）：
  1. `CURSOR_ERROR` + duration <10ms → 同命令重试一次；仍失败改替代路径（Shell Get-Content/Grep 限行、写临时脚本）；
  2. 统计失败签名时**先过滤 tool_name 为 null 的 TOOL_FAILURE 哨兵**（e3b0c442… = sha256("")），避免把空事件计入"跨会话重复"；
  3. 跨会话判定以**不同 observation 文件**为准（文件=会话），同文件多次不算跨会话。
- 被拒方案：把单次 CURSOR_ERROR 当命令失败进入诊断；为绕过 hook 修改 hook 本身。

## Evidence

- source_refs：上述 observations 文件；`obs_stats.py`（临时统计脚本，已删除）。
- 如何失效：当 hook 文本扫描修复（common.py BOM/UTF-8 边界）后瞬时失败消失时本条降级为历史。
