# 直接 uv run validator 输出 GBK 乱码：先设 PYTHONUTF8/PYTHONIOENCODING

## Problem

- 现象：PowerShell 下直接 `uv run --frozen --no-sync python -B .../validate_bundle.py`
  输出中文变乱码（`����`），命令 exit 0 但结果不可读。
- 上下文：2026-08-20 提交前验证；Windows PowerShell 默认代码页 GBK；
  validator 脚本用 `print` 输出中文。
- 影响：乱码掩盖 PASS/FAIL 语义，需要重跑才能确认结果。

## Solution

- 根因：Python 脚本 stdout 编码跟随控制台代码页（GBK），脚本内中文
  以 UTF-8 写入终端被错误解码；`PYTHONUTF8=1` 使 Python 以 UTF-8 模式
  运行，`PYTHONIOENCODING=utf-8` 固定 stdout/stderr 编码。单会话观察，
  与既有 42-command-encoding 规则一致（confidence 0.5）。
- 解法：
  1. 直接运行仓库 python 脚本前先设：
     `$env:PYTHONUTF8 = "1"; $env:PYTHONIOENCODING = "utf-8"`（PowerShell
     同一语句内用 `;` 分隔）。
  2. 经 `run_all_checks.py`（runner 内部已设两个 env）运行则无需手动
     设置（framework profile 输出正常即为实证）。
  3. 输出仍乱码时先修终端/环境编码再重试，不通过转换仓库文件编码
     掩盖问题。
- 被拒方案：`chcp 65001` 后不设 env（部分场景仍乱码）；把脚本输出
  改英文绕过（不解决编码根因）。

## Evidence

- source_refs：乱码输出（exit 0）+ 设 env 后正常中文输出 + runner
  内建 env 对照（`PASS [framework/validate_bundle]` 正常）。
- 如何失效：PowerShell 默认 UTF-8（Windows Terminal 新默认）、或脚本
  全部 ASCII 输出、或 CI 已设 env 后本条不再适用。
