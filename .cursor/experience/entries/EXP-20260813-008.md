# test_python_source_limits 300 行/50 行阈值超限 → 拆模块与提取辅助函数

## Problem

- 现象：`tests/tooling/test_python_source_limits.py` 对 `apps/services/packages/adapters/tests` 全树执行硬性检查——单文件 ≤300 行、函数体 ≤50 行；本会话新增/修改代码后 3 次独立运行分别报 `role_checks.py` 函数 62 行、`service.py` 317 行、`test_cancel_resume.py` 测试函数 59 行与 `test_fault_matrix.py` 363 行。
- 上下文：M7 独立复审会话为修复缺陷新增的守卫逻辑（budget release、resume 语义校验、fault 测试矩阵）集中写入已有模块，触发阈值。
- 影响：全量回归红灯，且该测试是 CI M0 gate 的一部分；阈值不可通过配置豁免（规则要求重构而非关 lint）。

## Solution

- 根因：新增逻辑直接堆进既有模块/函数，未按职责边界拆分；测试矩阵类文件天然长（12 个场景类）。同一会话 3 次独立 attempt 复现，未经跨会话复现。
- 解法：
  1. 函数超限：把守卫分支提取为独立纯函数（`_check_agent` → `_registration_findings`）。
  2. 文件超限：按单一职责拆模块（`service.py` → `convergence.py`（语义守卫+预算释放）+ `session_resolution.py`（team 解析辅助）+ `context.py`（RunContext DTO））。
  3. 测试文件超限：按场景族拆分（`test_fault_matrix.py`（F-01..07）→ 保留 + 新建 `test_fault_convergence.py`（F-08..12））。
- 被拒方案：调低断言（作弊）；把新测试塞进既有文件再压行（可读性崩坏）；给测试文件加豁免（规则禁止）。

## Evidence

- source_refs：本会话 3 次 `uv run --frozen --no-sync python -B -m pytest tests/` 的 FAIL 输出与重构后全量 988 passed。
- 如何失效：阈值规则调整、或 M0 落地 ruff/mypy 后以新工具链为准时本条不再适用。
