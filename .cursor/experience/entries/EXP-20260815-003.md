# tools/ 下脚本直接经 uv run 运行报 ModuleNotFoundError：sys.path 不含仓库根，改 exec(open) 或固化为测试文件

## Problem

- 现象：`uv run --frozen --no-sync python -B tools/tmp_xxx.py` 报
  `ModuleNotFoundError: No module named 'adapters'`；即使经 uv run（venv
  正确）仍失败，因为脚本文件位于 `tools/`，Python 把 `tools/` 加入
  sys.path 而非仓库根，仓库内包 `adapters/`、`packages/` 不可导入。
- 上下文：M9 独立复审安全探测（workspace 路径穿越、容器边界攻击）；
  Windows PowerShell + uv 0.11.18；`uv run --frozen --no-sync` 是仓库
  既定执行入口（EXP-20260813-001/002）。
- 影响：同一根因失败 2 次（同会话两次 attempt），每次先暴露一次无意义
  的 ModuleNotFoundError 后才找到正确执行方式。

## Solution

- 根因：Python 直接执行脚本时 sys.path[0] = 脚本所在目录（tools/），
  不是工作目录；仓库包按根目录布局（adapters/packages），故 import 失败。
  单会话观察，未经独立复现（confidence 0.5）。
- 解法：
  1. 临时探测：`uv run --frozen --no-sync python -B -c "exec(open('tools/tmp_xxx.py', encoding='utf-8').read())"`——cwd 为仓库根时 sys.path 含根目录（本会话成功路径）；或先 `sys.path.insert(0, 仓库根)`。
  2. 正式路径：探测代码直接固化为 `tests/` 下的正式测试（requires_docker
     marker），复用 pytest 的根路径注入，同时把攻击断言留作回归资产
     （本会话最终采用：test_docker_backend_security_e2e.py）。
- 被拒方案：反复尝试直接 `uv run python tools/xxx.py`（同签名失败 2 次）。

## Evidence

- source_refs：本会话两次失败输出（ModuleNotFoundError: No module named
  'adapters'）+ exec(open) 成功输出 + 固化测试 5 passed + m0 profile 全绿。
- 如何失效：若仓库改为 src-layout 或 `tools/` 下加入 `sys.path` 引导，
  或 Cursor/uv 改变脚本执行路径语义，本条不再适用。
