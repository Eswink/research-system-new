# Grep/Glob 传仓库根绝对路径确定性失败（os error 3），省略该参数或改传子路径即可

## Problem

- 现象：`Grep` 的 `path` 或 `Glob` 的 `target_directory` 传入**工作区根**绝对路径时，
  确定性返回 `rg: : IO error for operation on : 系统找不到指定的路径。 (os error 3)`，
  零结果。`D:\research-system`（反斜杠）与 `D:/research-system`（正斜杠）均失败。
- 上下文：Windows PowerShell 环境，工作区根 `d:\research-system`；跨模块检索任务
  （架构边界扫描、调用点定位）习惯性传绝对根路径。
- 影响：跨 4 个 observation 文件累计 14 次同签名失败（`784a8b47c701b4ee2656`），
  duration 40–116ms 全部落在正常执行区间——**不是瞬时故障**，重试同参数必然再失败。
  失败返回空结果而非报错中止，容易被误读为"仓库内无匹配"从而得出错误结论。

## Solution

- 根因（证据支持）：错误文本中冒号之间的路径为**空**（`IO error for operation on :`），
  说明工具将传入路径按工作区根做相对化后得到空字符串，并以空路径参数调用 rg。
  子路径相对化后非空，故正常工作。旁证：省略 `path` 时结果前缀为 `.\...`，
  传 `D:/research-system/.cursor/hooks` 时前缀为 `.cursor/hooks/...`——两者均为
  相对根的路径，与"根自身相对化为空"一致。
- 解法（稳定模式，本会话全部验证）：
  1. **检索整个仓库时省略 `path` / `target_directory`**——两个工具默认即为工作区根；
  2. 需要限定范围时传**严格位于根之下**的路径（目录或单文件均可），
     例如 `D:/research-system/.cursor/hooks`、
     `D:/research-system/adapters/sqlite/eval_report_store.py`——均成功；
  3. 该失败**不属于** EXP-20260823-003 的 CURSOR_ERROR 瞬时族，
     不要按"重试一次"处理（14/14 确定性复现）；先改参数再重试。
- 被拒方案：把反斜杠换成正斜杠（同样失败）；重试同一调用。
