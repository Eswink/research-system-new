# `uv run pip show <pkg>` 报 Package not found：验证安装版本改用 `uv run python -c importlib.metadata` 或读 uv.lock

## Problem

- 现象：`uv run --frozen --no-sync pip show openhands-sdk` 输出 `WARNING: Package(s) not found: openhands-sdk` 且 exit 1。
- 上下文：SA-1R 会话验证 openhands-sdk pin 与 UPSTREAM_COMPONENTS.yaml / qualification record 一致性时执行；PowerShell + uv 0.11.18 管理项目。
- 影响：误导性失败信号——包实际已安装（uv.lock 有 `version = "1.42.0"`，`.venv/Lib/site-packages` 存在，`import openhands` 成功），但 `pip show` 报找不到，阻塞版本核对。

## Solution

- 根因：单次观察，未经独立复现——`uv run pip show` 的 pip 子命令在 `--frozen --no-sync` 模式下的环境解析与 `uv run python` 不一致（疑似解析到非项目 venv 的 pip），导致查询不到项目依赖。
- 解法：
  1. 首选：`uv run --frozen --no-sync python -c "import importlib.metadata as m; print(m.distribution('<pkg>').version)"`（本会话成功输出 1.42.0）。
  2. 或直接读 `uv.lock` 中 `name = "<pkg>"` 段的 `version` 字段（确定性事实源）。
  3. 若必须用 pip：`uv run --frozen --no-sync python -m pip show <pkg>`（经项目 python 调用，未在本会话验证，作为备选）。
- 被拒方案：重试 `uv run pip show`；把 exit 1 当作"依赖未安装"处理（会误判供应链状态）。

## Evidence

- source_refs：本会话 `uv run --frozen --no-sync pip show openhands-sdk` 失败输出与 `uv run --frozen --no-sync python -c ... importlib.metadata ...` 成功输出（1.42.0）；`uv.lock:1262-1263` `name = "openhands-sdk"` / `version = "1.42.0"`。
- 如何失效：uv 修复 `uv run pip` 的环境解析、或改用 `uv run --python .venv pip show` 显式指定解释器时本条可能不再适用。
