# Python 探针/脚本必须用 .venv 的 python 并以临时 .py 文件执行，不用系统 python 与 `-c` 内联

## Problem

- 现象 1：`python -B -c "import openhands; ..."` 报 `ModuleNotFoundError: No module named 'openhands'`——裸 `python` 解析到系统 Python 3.11（`D:\environment\Python\Python311`），而 SDK 只装在项目 `.venv`。
- 现象 2：`python -B -c` 多行内联探针脚本（含 f-string/中文）在 PowerShell 下执行时，SDK 的 ASCII banner 与脚本 stdout 混入同一管道，`Select-String` 过滤结果被 banner 行干扰；且内联脚本无法干净重定向。
- 上下文：OpenHands SDK 行为验证（v1.42.0）、Event 流探针、SDK 异常模型确认；Windows PowerShell + uv 管理项目。
- 影响：反复 4 次独立失败（1 次模块缺失 + 2 次输出污染 + 1 次断言定位困难），阻塞对 SDK 真实行为的确认。

## Solution

- 根因：项目有 `.venv` 但 shell PATH 未优先；`python -c` 内联在 PowerShell 下换行/引号/编码行为不可控；SDK 启动打印 banner 到 stdout（`OPENHANDS_SUPPRESS_BANNER=1` 可关）。本会话 4 次观察，未经独立复现。
- 解法：
  1. 一律显式调用 `.venv` 解释器：`& d:\research-system\.venv\Scripts\python.exe -B <script>`；环境定位用 `where.exe python / uv` 先确认。
  2. 探针逻辑写成临时 `.py` 文件（如 `%TEMP%\sdk_probe_*.py`，`sys.stdout` 显式 `io.TextIOWrapper(..., encoding="utf-8", errors="replace")`），再整文件执行；不用 `python -c` 内联多行。
  3. 需要静默时把探针 stdout/stderr 重定向到 `io.StringIO()` 再打印结论行，或用 `$env:OPENHANDS_SUPPRESS_BANNER = "1"`。
- 被拒方案：`python -c` 内联多行（输出污染）；裸 `python`（模块缺失）；对 banner 行做字符过滤（脆弱）。

## Evidence

- source_refs：`d:\research-system\.venv\Scripts\python.exe -B -c "import importlib.metadata as m; print(m.version('openhands-sdk'))"` 成功（1.42.0）；`sdk_probe_run.py`/`sdk_probe_events.py` 临时文件成功输出 `run raised: ConversationRunError` 与事件流 `[created, started, message, message, succeeded]`。
- 如何失效：shell PATH 已优先 venv、或 SDK 移除 banner、或换 bash/zsh 时本条部分不适用。
