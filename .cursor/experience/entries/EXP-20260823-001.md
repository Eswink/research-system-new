# sqlite3 adapter 的 Timestamp/Row 序列化陷阱

## Problem

- 现象：新增 SqliteEvidenceLedger / SqliteMemoryStore 时连续 6+ 次失败——`Timestamp(value=datetime(...))` 写入 SQLite 后读回报 `AttributeError: 'str' object has no attribute 'tzinfo'`；`str(Timestamp)` 落库后 `datetime.fromisoformat` 报 `Invalid isoformat string: 'Timestamp(value=...)'`；mypy strict 报 `Returning Any ... no-any-return`。
- 上下文：`packages/domain/core.py` 的 `Timestamp` 是带 `__post_init__` 校验的 dataclass（要求 aware UTC），**不接受字符串构造**；`str(Timestamp)` 输出的是 dataclass repr 而非 isoformat。
- 影响：阻塞 M12-R1 WP9 持久化 adapter，反复修复 3 轮（本会话 6 次工具失败关联）。

## Solution

- 根因：`Timestamp` 无自定义 `__str__`；`sqlite3.Row` 索引返回 `Any`（mypy strict 报 no-any-return）。
- 解法（稳定模式，已固化为测试）：
  1. 序列化：`source.access_time.value.isoformat()`（**必须 `.value.isoformat()`，不是 `str(...)`**）；
  2. 反序列化：`Timestamp(datetime.fromisoformat(row["access_time"]))`；
  3. fetchone 返回：`assert isinstance(row, sqlite3.Row)` 后再返回（仓库既有 `SqliteArtifactStore._require_metadata` 同款模式）；
  4. 冲突比较：行重建后只比业务字段（access_time/captured_at 是观测元数据，幂等重登不误报冲突）。
- 被拒方案：`str(Timestamp)`（repr 不可逆）；`Timestamp(row["x"])`（字符串被 __post_init__ 拒绝）。

## Evidence

- source_refs：上述文件与测试；`tests/contracts/test_evidence_ledger_contract.py` / `test_ports_persistence.py` 双实现（Fake + Sqlite）110 passed。
- 如何失效：当 `Timestamp` 增加自定义 `__str__`/`fromisoformat` 或 SQLite 适配层改为 ORM 时本条不再适用。

## 备注

- 本条是经验缓冲，不是工程事实；重复 occurrence ≥2 时由 capture-learning 生成 LEARN proposal。
- 同类模式对任何带 `__post_init__` 校验的 domain 值对象（如 `Digest`、`ID`）适用：序列化前先确认其字符串形式契约。
