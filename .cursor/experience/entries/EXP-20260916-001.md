# 后台跑 Playwright 被 TaskStop 后子进程存活：共用日志文件会把两个 run 的输出混成不可判读的证据

## Problem

- 现象：为跑 GOAL-003 cycle 6 的 stub e2e（81 条），先起了一次后台运行，随后为了补一条
  用例把它 `TaskStop`。`TaskStop` 只结束了外层 shell：`npx playwright test` 与其
  `pnpm run dev` webServer **继续存活**。
- 第二次运行使用了**同一个日志路径**（`scratch/stub-e2e-cycle6.log`）。两个进程各自持有
  文件描述符并持续写入，日志出现「表头只有 1 个，但 81 条用例里既有 ok 又有 x/-」的
  自相矛盾状态；`grep -c '^  ok'` 的读数在两个 run 之间漂移。
- 影响：该日志**不能作为门禁证据**——无法判断"到底哪一次跑完了、失败的是谁"。
  这是"看起来像失败/像成功"的假象，比直接报错更危险。

## Solution

- 判定"后台 run 是否真的死了"不要看任务状态，看进程与日志两条证据：
  1. 进程：`powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter \"Name='node.exe'\" | Select-Object ProcessId,CommandLine"`，
     找 `playwright test` / `run dev --port` 的命令行；
  2. 日志：`grep -c "Running .* tests using" <log>` —— 同一次运行只有**一个**表头，
     出现两个表头即已被并发写坏。
- 清理：按 PID `taskkill //T //F //PID <n>`（Git Bash 下 flags 要写成 `//T //F`）。
  **不要**按镜像名批量杀 `node.exe`——ZCode 自身的 MCP server 也是 node（本例中 PID 36976）。
- 预防：每次运行用**唯一**日志文件名（`…-final.log`、带 cycle/时间戳），
  并且不要 `TaskStop` 正在写日志的 Playwright 运行——让它跑完，或先杀进程再重定向。

## Evidence

- source_refs：上列三条（进程清单、混写日志形态、清理后计数归 0）。
- 失效条件：若后台任务管理器改为整树结束进程（或在容器/WSL 里跑 Playwright 不需要
  `pnpm run dev` 子进程），本条前半失效；唯一日志文件名的做法永远成立。
