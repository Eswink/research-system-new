# docker daemon 不可用时：pytest 以 `-m "not requires_docker"` 排除 docker 套件重跑

## Problem

- 现象：Windows 本机 Docker Desktop 未启动时 `docker version` 报
  `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine`；
  全量 pytest（`run_all_checks.py --profile python`）中 docker 测试大量
  E（error），且后续长时间无输出。
- 上下文：2026-08-20 提交前验证（IG-1 seam 含 docker 集成测试）；Windows
  PowerShell + uv 0.11.18；pytest 9.1.1。
- 影响：本机 docker 不可用是环境常态而非代码失败，直接跑全量 pytest
  会挂起/全 E，浪费验证时间。

## Solution

- 根因：Docker Desktop 引擎未运行（npipe 不存在），docker-py 连接
  失败；Windows 下连接超时路径较长（见 EXP-20260815-002 的 npipe
  异常语义）。单会话观察，未经独立复现（confidence 0.5）。
- 解法：
  1. 先快速探测 daemon：`docker version --format "{{.Server.Version}}"`
     —— 秒级失败即可判定不可用，不必等 pytest。
  2. 不可用时：`uv run --frozen --no-sync python -B -m pytest -q -m
     "not requires_docker"` 跑全量（本会话 exit 0，1660 collected 减
     docker 集）。
  3. docker 专项验证（container-quality：sandbox 镜像构建 +
     requires_docker 测试）留给 CI job，本机不强行补跑。
- 被拒方案：直接跑全量 pytest（docker 测试 E + 挂起）。

## Evidence

- source_refs：docker CLI 连接失败输出 + `-m "not requires_docker"`
  全量 exit 0 + ruff/mypy strict 369 files PASS + framework profile 8/8。
- 如何失效：本机启动 Docker Desktop 后应跑 docker 集；若 CI 移除
  container-quality job 或 docker 测试改为非 requires_docker，本条不再
  适用。

## 备注

- 本条是经验缓冲，不是工程事实；occurrences=1（单会话观察）。
- 与 EXP-20260815-002 区分：该条是 docker-py `wait(timeout=)` 在
  Windows npipe 的异常类型问题（代码层）；本条是 daemon 未运行时的
  验证策略（环境层）。
