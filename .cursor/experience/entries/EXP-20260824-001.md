# 标题：含 `.env` 字样的命令被 shell guard fail-closed 拦截；AwaitShell 阻塞参数必须传整数

## Problem

- 现象：本会话（M12-R1 re-audit）中 3 次 Shell 命令被安全门禁 hook 拒绝：
  `git check-ignore -v .env.local`、`git status --porcelain -- .env.local`、
  `Get-ChildItem -Force -Name .env*`，拒绝原因均为"禁止 shell 命令访问或引用
  真实凭据/私钥路径"（fail-closed，未执行）。
  另有 2 次 `AwaitShell` 调用因 `block_until_ms` 传了浮点
  `90000.0` 报 `block_until_ms must be an integer`（未等待即返回错误）。
- 上下文：验证本地凭据文件是否被 gitignore 时；后台命令等待时。
- 影响：含 `.env` 路径的 git/文件验证命令全部无法直接执行；AwaitShell 等待失效。

## Solution

- 根因：shell_guard/secret_guard 对命令文本做敏感模式扫描，`.env*` 属于
  凭据路径模式，命中即 fail-closed 拒绝（与 EXP-20260822-001 的 Read 拦截
  同族，安全边界正确，不绕过）。AwaitShell 的 `block_until_ms` 参数要求
  int，float 被严格拒绝。
- 解法：
  1. 验证 gitignore 忽略效果时**不引用 `.env` 字样**：直接跑全量
     `git status --porcelain`，凭据文件不出现（既不在 M 也不在 ??）即
     证明已被忽略；需要确认忽略规则时用 `.gitignore` 内容推理
     （`.env.*` 覆盖 `.env.local`），不执行针对该路径的 git 命令。
  2. 后台等待统一用 `block_until_ms` 传**整数**（如 `90000` 而非 `90000.0`），
     或改用前台 Shell 的 `block_until_ms` 参数。
  3. 被 hook 拦截时不重试同命令、不改 hook（EXP-20260821-002 已确立），
     改用替代命令或替代验证路径。
- 被拒方案：重试相同含 `.env` 路径的命令（必然再次被拒）。

## Evidence

- source_refs：本会话工具调用记录（Shell 拒绝 ×3 / AwaitShell 参数错误 ×2）；
  `.gitignore` 第 2 行 `.env.*` 规则；EXP-20260822-001（同族 Read 拦截，SUPERSEDED）。
- 如何失效：若 shell_guard 改为只拦真实存在的凭据文件内容（而非路径字样），
  或 AwaitShell 接受 float，本条可能不再适用。
