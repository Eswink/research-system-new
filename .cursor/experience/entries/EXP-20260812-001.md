# 经验库闭环端到端回归方法（失败→观察→提示→沉淀→注入）

## Problem

- 现象：经验库闭环（`postToolUseFailure` 自动观察 → `distillation_gate` stop 提示 → `capture-experience` 沉淀 → `sessionStart` 摘要注入）仅有单点 eval 覆盖，缺少一次真实环境端到端回归。
- 上下文：新增 `.cursor/hooks/distillation_gate.py` 与 `.cursor/experience/` 后，需要证明各环节在真实 payload 下按序工作，且不会重复提示或泄漏原始错误文本。
- 影响：若闭环在真实会话中失效（如 marker 不落盘导致反复提示、或 INDEX 解析失败导致注入缺失），无法被单元 eval 发现。

## Solution

- 根因：闭环各环节各自可测，但衔接点（hook 输出 → runtime 文件 → skill 写入 → sessionStart 读取）未被整体验证。单次观察，未经独立复现。
- 解法（三步回归）：
  1. 用官方 `postToolUseFailure` 字段（`conversation_id`/`tool_name`/`duration`/`failure_type`/`error_message`/`is_interrupt`）调用 `failure_observer.py`，确认 observations JSONL 落盘且无原文泄漏；
  2. 用 `stop` 事件（`status: completed`, `loop_count: 0`）调用 `distillation_gate.py`，确认输出一次 `followup_message`；再次调用确认返回 `{}`（marker 去重）；跨会话相同 `error_signature` 时应提示 LEARN；
  3. 按 `capture-experience` 流程写入 `EXP-YYYYMMDD-NNN` 条目并更新 `INDEX.md`，再用 `sessionStart` payload 调用 `session_context.py`，确认 `additional_context` 含"工程经验库 N 条"摘要（≤5 条）。
- 回归发现并修复的真实缺陷（2026-08-12）：`session_context.py::_experience_summary` 原用 `line.strip("| ").split("|")` 解析 `INDEX.md` 表格行，`strip("| ")` 会剥掉行尾管道符导致 split 后仅 6 列（<7 被跳过），摘要注入静默失效；改为 `stripped[1:].split("|")` 保留尾列后恢复。教训：单点 eval 未覆盖 sessionStart 注入，端到端回归必要。
- 被拒方案：无（该闭环尚无替代设计）。

## Evidence

- source_refs：上述 hook 与 skill 源码；`run_cursor_framework_evals.py` / `run_cursor_hook_evals.py` 的 distillation 断言段（FRAMEWORK EVAL PASS / HOOK EVAL PASS）。
- 真实会话观测：本次回归中发现 `.cursor/runtime/observations/<cid>.jsonl` 已由 `postToolUseFailure` 自动记录本会话两次 Shell `CURSOR_ERROR`（validator 退出码 1、PowerShell here-string 语法错误），无需人工写入——自动观察层在真实环境有效。
- 如何失效：当 hook 事件字段、`safe_id` 规则、`INDEX.md` 表格列序或 skill paths 变化时，本条回归步骤需随之更新；`review_after` 到期后先复检再引用。
