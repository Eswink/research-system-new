# distillation_gate 的失败计数与「≥2 次会话」文案与其自身实现不一致（过报）

## Problem

- 现象：stop 提示「本会话有 3 次工具失败；…有 2 类失败签名已在 ≥2 次会话中出现」。
  按 observation 语料实测：本会话 7 个签名**全部**只出现 1 次（hook 在 17:07:12Z
  触发时文件仅 3 行，其后又追加 4 行）；全语料中
  `count >= 2` 的只有 2 个签名，其中
  - `784a8b47c701b4ee2656`：14 命中 / 4 个会话文件（真实失败类，见 EXP-20260830-001）；
  - `e3b0c44298fc1c149afb`：2 命中 / **1 个**会话文件，`tool_name: null`、
    `duration_ms: 0.0`、`error_class: TOOL_FAILURE`——即 sha256("") 空载荷哨兵。
- 上下文：`.cursor/hooks/distillation_gate.py` 生成 stop followup；
  agent 依据该提示决定是否运行 capture-experience / capture-learning。
- 影响：三处过报/错报，会把 agent 导向错误的沉淀对象——
  1. 「N 次工具失败」是**原始行数**（`len(splitlines())`，不解析 JSON、不过滤哨兵），
     哨兵行与畸形行都被计入；且随会话推进而漂移——本例 hook 报 3，
     该会话文件最终为 7 行（6 条 Read fail-closed + 1 条 Shell）；
  2. 「≥2 次**会话**」与实现不符：`_repeated_signatures()` 只做
     `counts[sig] += 1` 后取 `count >= 2`，**没有会话维度**；本例中哨兵的 2 次命中
     恰好同属一个会话文件，却被表述为跨会话；
  3. `_repeated_signatures()` 的结果**未与本会话签名求交**，因此提示可能建议
     针对与当前会话无关的签名生成 LEARN 提案——本例正是如此：
     本会话 7 个签名全部 `count == 1`，而被提示的 2 类**都不在**本会话中。

## Solution

- 根因（源码级定位，非推测）：
  - `distillation_gate.py:13-21` `_session_failures` 直接返回文件行数；
  - `distillation_gate.py:24-38` `_repeated_signatures` 缺少 EXP-20260823-003
    已确立的 `tool_name is None` 哨兵过滤，且以总命中数而非 distinct 文件数为阈值；
  - `distillation_gate.py:104-119` 文案写「≥2 次会话」，强于代码实际计算的属性。
- 解法（当前会话内可用的稳定模式，不改 hook）：
  1. 收到该提示后**不要直接采信计数**；先用只读聚合复核：
     `uv run --frozen --no-sync python -B scratch/obs_signature_report.py`
     （按 `tool_name is None` 过滤哨兵，并按 distinct observation 文件计会话数）；
  2. 只对复核后仍满足「同签名跨 ≥2 个 observation 文件 + 已有稳定解法」的类
     生成 LEARN 提案；
  3. 读取 `.cursor/runtime/**` 一律用 Shell `Get-Content`（EXP-20260827-001）。
- 附带发现：`FRONTMATTER_SIGNATURE_RE`（`distillation_gate.py:10`）只捕获首个
  20-hex，故 EXP-20260827-001 中 pipe 拼接的第 2–5 个签名**永不**被
  `_matching_experience` 命中；多签名条目的「经验库匹配」提示会漏报。
- 被拒方案：直接修改 `distillation_gate.py` 使计数与文案一致——本轮不做，
  Hook 变更须走 capture-learning → promote-learning 门禁并取得显式授权。

## Evidence

- source_refs：上列 hook 源码行；实测命中分布由
  `scratch/obs_signature_report.py` 与 `scratch/obs_signature_trace.py` 产出
  （只读脚本，`uv run --frozen --no-sync` 执行）。
- 关键量化：`observation files with real rows: 7`、`distinct error_signature: 77`、
  `all signatures spanning >= 2 sessions:` 仅 `784a8b47c701b4ee2656`。
- 如何失效：若 `_repeated_signatures` 增加哨兵过滤/会话维度，或文案改为
  「≥2 次出现」，本条大部分内容失效；`safe_signature` 改为对错误文本做
  路径归一化后，签名的路径敏感性结论亦需重测。
