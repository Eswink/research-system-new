# 长阻塞 Shell 返回 MainThreadCursor disposed 时先确认命令是否执行，再决定重跑

## Problem

- 现象：`block_until_ms=900000` 的前台 Shell 调用（m0 profile 全量检查）返回 `exec throw: MainThreadCursor disposed while stream <uuid> was active`，exit 通道无任何 stdout/stderr/exit_code，命令实际未执行。
- 上下文：Windows PowerShell + Cursor IDE 侧执行通道；命令本身（`run_all_checks.py --profile m0`）在其他时刻可正常完成（本会话后续两次成功，约 120s）。
- 影响：若误判为"检查失败"会导向错误诊断；实际是 IDE 执行通道瞬时故障，与命令/仓库状态无关。

## Solution

- 根因：IDE 侧 stream 生命周期异常（dispose 早于命令完成）；单次观察，未经独立复现。
- 解法：返回 `exec throw: MainThreadCursor disposed` 且无任何命令输出时，不把它当作命令失败——直接同命令重跑；重跑前可读 `terminals/` 目录文件确认上一条命令是否留下执行痕迹（exit_code/输出）。
- 被拒方案：无（未尝试修复 IDE 侧，重跑即恢复）。

## Evidence

- source_refs：本会话 Shell 调用记录（失败 1 次 → 同命令重跑 2 次均成功，m0 profile 18/18 PASS）。
- 如何失效：IDE 版本升级改变执行通道行为后本观察可能不再适用；若出现稳定复现（同签名 ≥2 次独立发生）需重新评估根因，不应继续"重跑即可"。
