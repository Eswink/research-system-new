# 全量 pytest 在 docker 测试处长时间无输出：taskkill 进程树 + 排除 docker 重跑

## Problem

- 现象：`run_all_checks.py --profile python` 的 `python/tests` 检查
  （全量 pytest）在 docker 测试大量 E 之后长时间无新输出（AwaitShell
  轮询 10+ 分钟仍 running，输出行停在 e2e 中间）。
- 上下文：2026-08-20 提交前验证；Windows PowerShell；本机无 docker
  daemon（EXP-20260820-001 同环境）。
- 影响：挂起使验证流程阻塞，无法获得 python profile 的最终 PASS/FAIL。

## Solution

- 根因：docker 连接失败在部分测试路径上不是快速 error 而是长时间
  等待/重试（Windows npipe 语义见 EXP-20260815-002），pytest 被拖住。
  单会话观察，未经独立复现（confidence 0.5）。
- 解法：
  1. 识别挂起特征：输出中 docker 测试（adapters/execution、
     test_execution_backend_docker 等）已出现 E，且后续长时间零新增行。
  2. 终止：`taskkill /PID <runner-pid> /T /F`（/T 连子进程树一起杀；
     runner 是 `uv run` 包装，直接杀外层会留 python 子进程）。
  3. 重跑：`pytest -q -m "not requires_docker"`（同 EXP-20260820-001），
     exit 0 拿到全量（非 docker）结果。
- 被拒方案：继续 AwaitShell 长轮询等待（无产出）；仅杀外层进程不杀
  子进程树（残留 pytest 占用）。

## Evidence

- source_refs：挂起输出（停在 e2e 后无新行）+ taskkill 输出（7 个
  子进程全部 SUCCESS terminated）+ 排除重跑 exit 0。
- 如何失效：docker daemon 可用（挂起消失）、或 CI/pytest 为 docker
  连接设置短超时、或本机移除 docker 测试集后本条不再适用。
