# PatchEdit 报 "historical edit error omitted from replay" 时重新 Read 文件后再编辑

## Problem

- 现象：PatchEdit 调用返回 `historical edit error omitted from replay; re-read the file before editing`，编辑未生效。
- 上下文：同一文件在前一轮已被 ruff `--fix`/`format` 自动改写，或此前编辑与当前 old_string 之间文件已变化；本次会话 3 个不同文件（__init__.py、OPENHANDS_ADAPTER.md、test_usage_ledger.py）均出现。
- 影响：编辑被拒绝，若继续用旧内容重试会二次失败或误改。

## Solution

- 根因：PatchEdit 依赖"最近一次 Read 的精确内容"做匹配；文件被工具链（ruff format、其他工具）改写后，会话内缓存的旧快照失效。本会话 3 次观察，未经独立复现。
- 解法：
  1. 收到该错误后，先用 Read 重新读取目标文件（必要时带 offset 定位）；
  2. 从新内容复制精确 old_string 再 PatchEdit；
  3. 若文件刚被批量格式化，可考虑整段替换或改用 Write（仅当重写全文件）。
- 被拒方案：凭记忆重试同一 old_string（继续报同一错误）；直接 Write 覆盖（有覆盖无关用户改动的风险）。

## Evidence

- source_refs：`adapters/openhands/__init__.py`（ruff --fix 后重读成功）、`docs/integration/OPENHANDS_ADAPTER.md`（历史编辑错误后重读成功）、`tests/adapters/openhands/test_usage_ledger.py`（ruff format 后重读成功）——三处均以"Read → PatchEdit"闭环。
- 如何失效：编辑器工具行为变化、或文件不再被外部工具改写时本条不再适用。
