# 长时后台 Shell 轮询：AwaitShell 收不到事件时直接读取 terminals 文件

## Problem

- 现象：`block_until_ms: 0` 启动长时命令（约 1-2 分钟的 m0 profile 全量回归）后，Shell 返回 `Missing terminal shell stream event (expected exit or backgrounded)`；随后多次 `AwaitShell`（60s/120s/180s/240s）持续返回 `stillRunning` 且不给出任何累计输出，无法判断任务是正常执行还是挂起。
- 上下文：Windows PowerShell + Cursor 终端后台化；命令为 `uv run --frozen --no-sync python -B ... run_all_checks.py --profile m0 --keep-going`。
- 影响：本会话两次出现（首轮系统 python 失败轮与 uv 重跑轮），浪费多轮等待，且无法在等待中看到进度。

## Solution

- 根因：单次观察，未经独立复现——后台化瞬间终端流事件未回传（shell-incomplete），AwaitShell 的 pattern 匹配依赖累积输出，长时无新输出的阶段表现为 stillRunning。
- 解法：
  1. 直接读取终端文件确认状态：`C:\Users\googl\.cursor\projects\d-research-system\terminals\<id>.txt`（文件头含 pid / status / running_for_ms；文件尾出现 `exit_code` 与 `ended_at` 表示完成）。
  2. 看最新进度用 `Get-Content <file> -Tail 40`；注意终端文件可能以 ANSI/非 UTF-8 呈现中文乱码，结论行（PASS/FAIL/exit_code）不受影响。
  3. 也可用长 `block_until_ms`（180-300s）一次性 AwaitShell 代替多次短轮询；若仍超时则回到读文件。
- 被拒方案：无限短超时轮询 AwaitShell（事件丢失时死等）；按 `running_for_ms` 无进展猜测（无证据）。

## Evidence

- source_refs：两次 shell-incomplete 现象与读取 terminals 文件后确认运行状态/exit_code 的对比（本会话终端输出）。
- 如何失效：Cursor 终端后台化行为修复（事件正常回传）或 AwaitShell 支持无输出存活后不再需要此变通。
