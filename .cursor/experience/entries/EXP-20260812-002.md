# Windows PowerShell 下 git 命令写法：`;` 分隔与 `git commit -F`

## Problem

- 现象：两条 git 命令在 PowerShell 下直接报 ParserError（`标记"&&"不是此版本中的有效语句分隔符`；`重定向运算符后面缺少文件规范`）。
- 上下文：`git status --short && git log --oneline -8` 与 `git commit -m "$(cat <<'EOF' ...)"`；Windows PowerShell 5.x。
- 影响：多命令串联与长 commit message 传递失败，阻塞提交流程（本会话 2 次独立失败，同根因）。

## Solution

- 根因：PowerShell 不支持 bash 的 `&&` 串联与 `<<'EOF'` heredoc；单次观察 + 权威依据（PowerShell 语法规范），未经独立复现。
- 解法：
  1. 多命令串联改用 `;`：`git status --short; git log --oneline -8`（本会话后续多次成功）。
  2. 长 commit message 改用 message 文件：先写 `commit-msg.txt` 再 `git commit -F <path>`；避免在命令行内嵌多行文本与引号嵌套。
- 被拒方案：`&&` 串联（ParserError）；heredoc 内嵌 `$(cat <<'EOF')`（ParserError）。

## Evidence

- source_refs：本会话终端输出（ParserError 两处）；本会话成功路径 `git commit -F`（提交 1035a64、c31c8b7）；`.cursor/rules/42-command-encoding.mdc`（"只有确认当前 shell 支持时才使用 &&"约束）。
- 如何失效：切换到 bash/zsh 终端时本条目不适用（`&&` 与 heredoc 合法）；git 或 PowerShell 行为变化时需复核。
