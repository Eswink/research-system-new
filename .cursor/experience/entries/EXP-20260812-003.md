# ruff lint 作用域必须按 CI 定义，禁止全仓 `ruff check .`

## Problem

- 现象：`ruff check .` 报 548 errors，绝大多数位于 `.cursor/skills/*/scripts/` 与 hooks（line-too-long 等）。
- 上下文：手工执行 lint 时未带路径参数；`.cursor/skills` 脚本豁免行数/CCN 门槛（Python Rule），但 `ruff check .` 会扫描它们。
- 影响：制造虚假红灯，干扰对真实 product code lint 状态的判断。

## Solution

- 根因：lint 作用域与豁免配置不一致——CI 只对 product roots（`packages adapters tests`）跑完整规则，对 `.cursor/hooks`/`.cursor/skills` 只跑 `--select F,I`；单次观察，未经独立复现。
- 解法：lint/format 一律按 CI 入口执行：
  1. `python -B .cursor/skills/cursor-framework-check/scripts/run_all_checks.py --profile m0 --keep-going`（权威入口，覆盖 lint/format/typecheck/tests/framework）；
  2. 局部快速检查用显式路径：`ruff check packages adapters tests`、`ruff check .cursor/hooks .cursor/skills --select F,I`；
  3. 避免无路径的 `ruff check .` / `ruff format --check .`。
- 被拒方案：直接修 `.cursor/skills` 内的 line-too-long（豁免区，改它只是掩盖作用域问题）。

## Evidence

- source_refs：`run_all_checks.py::python_checks`（python/engineering-lint 与 python/product-lint 的目标定义）；本会话 `m0` profile 最终 19/19 PASS（按此作用域）。
- 如何失效：CI 脚本调整 lint 目标、或 `.cursor/skills` 纳入完整 lint 时本条不再适用。
