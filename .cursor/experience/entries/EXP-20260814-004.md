# m0 profile 正确入口是 run_all_checks.py --profile m0 --keep-going（不存在 run_m0_profile.py）

## Problem

- 现象：运行 `.cursor/skills/cursor-framework-check/scripts/run_m0_profile.py`
  报 exitCode 2（文件不存在），目录下实际脚本为 `run_all_checks.py`、
  `validate_cursor_framework.py` 等 5 个。
- 上下文：按名称猜测 m0 profile 入口脚本不存在；即使使用
  `uv run --frozen --no-sync`（EXP-20260813-001 的正确执行环境）也无法
  规避脚本名错误。
- 影响：m0 profile 回归多一次失败往返，需从 CI 定义回查正确入口。

## Solution

- 根因：入口脚本名与 profile 名不同，凭记忆猜测。单次观察，未经独立
  复现。
- 解法：m0 profile 权威入口为
  `.cursor/skills/cursor-framework-check/scripts/run_all_checks.py
  --profile m0 --keep-going`，与 `.github/workflows/m0-quality.yml`
  的 CI 定义一致（`--keep-going` 保证全项执行而非首败即停）。
- 通用模式：运行任何 profile/门禁前先查 CI workflow 定义
  （`.github/workflows/m0-quality.yml`），CI 中写死的命令即为权威入口。

## Evidence

- source_refs：本会话 exitCode 2 输出 → 修正入口后 18/18 PASS
  （2026-08-14）；`.github/workflows/m0-quality.yml` 命令定义。
- 如何失效：脚本入口改名或 profile 定义迁移后本条不再适用。
