# OpenHands SDK 测试脚手架：pydantic 判别联合的 Action/Observation 必须用具体子类

## Problem

- 现象 1：自定义工具 executor 返回 `Observation.from_text("...")` 时抛 `pydantic ValidationError: Unknown kind '' for openhands.sdk.tool.schema.Observation; Expected one of: [...]`。
- 现象 2：直接构造裸 `Action()` 传 SDK `execute_tool` 抛同族错误 `Unknown kind '' for ... Action`。
- 上下文：自定义测试工具（echo/slow 工具）的 action_type/observation_type；SDK v1.42.0 `schema.py` 的 Action/Observation 是 pydantic 判别联合（discriminated union），基类不可直接实例化。
- 影响：两次独立失败，测试脚手架搭建被阻塞。

## Solution

- 根因：SDK 工具模型是判别联合，`kind` 由具体子类决定；基类 `from_text`/裸构造无法推断 kind。本会话 2 次观察，未经独立复现。
- 解法：
  1. 为每个测试工具定义具体子类：`class _MockEchoAction(Action)`、`class _MockEchoObservation(Observation)`；
  2. executor 返回具体子类实例（`_PolicyEchoObservation.from_text("ok")` 或 `cls(...)`），不直接返回基类；
  3. direct execution 测试传入具体 Action 子类实例（如 `_PolicyEchoAction(text="x")`），不裸构造基类。
- 被拒方案：`Observation.from_text`（kind 为空）；裸 `Action()`（kind 为空）；给基类手动塞 `kind` 字段（pydantic 不允许基类实例化）。

## Evidence

- source_refs：`tests/adapters/openhands/test_policy_enforcement.py`（修复后 5 passed）、`test_error_cancel_integration.py`（SlowPolicyEchoTool 同模式）；`.venv\Lib\site-packages\openhands\sdk\tool\schema.py` 判别联合定义。
- 如何失效：SDK 改判别联合为普通基类、或测试工具改用 SDK built-in 工具时本条不再适用。
