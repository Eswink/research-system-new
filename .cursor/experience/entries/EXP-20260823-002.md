# 构造契约签名先行验证：断言失败先跑真实值/读 domain 定义

## Problem

- 现象：本会话 5+ 次测试构造失败——`TypeError: ToolCallRecord.__init__() missing 1 required positional argument: 'capability'`、`FrozenConditions.__init__() missing 1 required positional argument: 'input_digests'`、`ValueError: invalid UUID: '5a1c6a8e-...-12121212-222'`（ID 强制 UUID4）、断言 `claim_id == claim:{run_id}` 实际为 `claim:{experiment_run_id}:result`。
- 上下文：M12-R1 新增 8 个测试文件与 clean-run harness，大量构造 domain/Port 对象；契约必填字段与 ID 派生规则不在记忆里。
- 影响：每轮失败浪费 1 个测试运行周期；clean_run 的 ID 派生还导致 3 轮连续修复。

## Solution

- 根因：Domain 值对象（ID/Digest/Timestamp）有严格 `__post_init__` 不变量；`_claim_for_run` 等派生 id 规则（`claim:{experiment_run_id}:result`）以真实 admission 实现为准，不是直觉约定。
- 解法（稳定模式）：
  1. 写测试构造前先 Grep/Read 对应 `dataclass` 定义与 `__post_init__`（必填字段清单）；
  2. 派生 ID 必须生成合法 UUID4（8-4-4-4-12，仅 hex），不要拼接任意前缀；
  3. 断言与真实派生规则冲突时，先跑一次获取真实值再固化断言（本会话 claim/artifact id 均为如此）；
  4. 长构造函数用参数对象（本仓库已有 `*Input` dataclass 模式）。
- 被拒方案：`__import__` 内联取类（行长与可读性差，仍会漏必填字段）。

## Evidence

- source_refs：上述文件；最终 `tests/application/test_m12_clean_run.py` 5 tests 全过。
- 如何失效：当 Domain 构造契约变更（加/删必填字段）时本条提醒仍有效，但具体字段清单需重新核对。
