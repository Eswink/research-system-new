# pytest 收集失败两类：同名测试模块 import file mismatch 与 fixture 导入位置错误

## Problem

- 现象 1：`pytest tests/` 收集报 `import file mismatch: imported module 'test_fault_injection' has this __file__ attribute ... tests\adapters\openhands\test_fault_injection.py which is not the same as the test file we want to collect: tests\e2e\test_fault_injection.py`——两个目录存在同名测试模块（basename 相同）。
- 现象 2：同一文件还从 `tests.e2e.scenario` 导入 `m7_catalog` 等 fixture，但这些符号实际定义在 `tests.e2e.scenario_catalog`（`ImportError: cannot import name 'm7_catalog'`）。
- 上下文：M7 独立复审会话全量回归；`tests/adapters/openhands/test_fault_injection.py` 与 `tests/e2e/test_fault_injection.py` 同名冲突，为 M7 开发窗口遗留。
- 影响：同名冲突导致整个 `tests/` 收集中断（exit 2），全量回归无法启动；导入位置错误使该 E2E 文件单独收集也失败。

## Solution

- 根因：pytest 以模块 basename 导入测试文件，`tests/` 下两个 `test_fault_injection.py` 触发 import 缓存冲突；fixture 函数未按模块职责归位（E2E harness 的 catalog fixture 在 `scenario_catalog.py`，不在 `scenario.py`）。单次观察，未经跨会话复现。
- 解法：
  1. 同名冲突：重命名其中一个文件（本会话 `tests/e2e/test_fault_injection.py → test_fault_matrix.py`），禁止在 `tests/` 树内重复使用测试模块 basename。
  2. 导入位置：测试文件只从定义模块导入符号（`from tests.e2e.scenario_catalog import m7_catalog, ...`；`scenario.py` 只导出 harness/runtime/protocol）。
- 被拒方案：修改 `pytest.ini`/`conftest.py` 关掉冲突检测（掩盖问题）；把 fixture 复制到 `scenario.py`（双份维护）。

## Evidence

- source_refs：本会话两次收集失败输出与重命名/修正导入后全量 988 passed（`uv run --frozen --no-sync python -B -m pytest tests/ -q`）。
- 如何失效：项目引入唯一测试目录布局、或 pytest 版本改变收集行为时本条不再适用。
