# OpenHands 相关 pytest 失败诊断：用 -q --tb=line + 输出落盘/过滤，避免 SDK 可视化 stdout 淹没

## Problem

- 现象：运行 OpenHands adapter 测试失败时，pytest 输出包含 SDK 的完整 System Prompt、Agent Action、Observation 可视化文本（每次数 KB 至 79KB+），真正错误堆栈被淹没在中间；直接管道 `Select-Object -Last N` 截断后经常只看到可视化输出而看不到断言行。
- 上下文：SDK LocalConversation 默认 visualizer 向 stdout 打印会话内容；失败断言在堆栈中，位于 Captured stdout 之前。
- 影响：三次独立失败诊断受阻（test_policy_enforcement、test_fork_override、test_error_cancel_integration），拖慢定位。

## Solution

- 根因：SDK 默认可视化输出量大且与 pytest 捕获输出混排；`-q` 只压缩测试进度不压缩 captured stdout。本会话 3 次观察，未经独立复现。
- 解法：
  1. 失败诊断优先用 `--tb=line`（一行一错）或 `--tb=short`，配合 `Select-String -Pattern "Error|assert|FAILED|passed|failed"` 过滤关键行；
  2. 需要完整堆栈时把输出写文件再按段落读：`pytest ... 2>&1 | Out-File -Encoding utf8 out.txt`，用 Read 工具定位（避免管道截断）；
  3. 根治噪音：测试代码用 `redirect_stdout/redirect_stderr` 包裹 SDK 调用，或构造 `Conversation(visualizer=None)`；`-p no:cacheprovider` 无助于 stdout，不采信。
- 被拒方案：`Select-Object -Last 5` 直取尾部（截断后只见 Captured stdout）；加大终端缓冲（治标不治本）。

## Evidence

- source_refs：本会话 `--tb=line` 成功定位 `test_fork_override`（KeyError ToolDefinition not registered）与 `test_policy_enforcement`（ValidationError Unknown kind）的具体行；`Out-File` 落盘后读取定位 `test_error_cancel_integration` 的 SESSION_FAILED 计数断言。
- 如何失效：SDK 关闭默认可视化、或 pytest 版本调整捕获输出格式时本条部分不再适用。
