# git diff 输出为空但 git status 显示修改 = 纯 CRLF/LF 行尾差异

## Problem

- 现象：`git status --short` 显示 3 个 Python 文件 modified，但
  `git diff -- <paths>` 输出为空（仅 stderr 出现
  "CRLF will be replaced by LF" 警告），无法判断是否真有内容改动。
- 上下文：Windows 工作区，文件被工具以不同行尾写回；git 默认不把纯
  行尾变化渲染为内容 diff。
- 影响：提交前审查时误判"无实质改动"，或反向误判为 diff 命令失效而
  重复排查。

## Solution

- 根因：Windows CRLF 与仓库 LF 的行尾归一化。单次观察，未经独立
  复现。
- 解法：diff 为空但有 CRLF 警告时，用 `git diff --stat` 或
  `git diff --numstat` 验证改动行数；行数极小且与警告一致时判定为
  纯行尾差异。审查内容时可用 `git diff --ignore-cr-at-eol`。
- 提交语义：纯行尾归一化文件不产生实质内容差异，commit message 中
  显式注明"line ending normalization, no content change"。

## Evidence

- source_refs：本会话 git 命令输出（CRLF 警告 + 空 diff）；
  提交 9fa7413 的 commit message 已注明行尾归一化。
- 如何失效：仓库统一 `.gitattributes` 强制行尾后，此类 diff 不再出现。

- 本条是经验缓冲，不是工程事实；occurrences=1（单会话观察）。
- 通用模式：Windows 下任何"status 显示修改但 diff 为空"都应先怀疑
  行尾差异，再看 `--stat` 数字确认。
