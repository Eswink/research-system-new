# validate_bundle / governance validator 全仓扫描陷阱：文档禁止旧版本号与未勾选项字面量

## Problem

- 现象：本会话两次独立运行 validator 失败（exitCode 1）：
  1. `validate_bundle.py` 报 `Markdown 本地链接不存在`、`INDEX 引用不存在`、`发现旧项目版本引用: .cursor\plans\rechecks\RECHECK-20260814-009-...`；
     `governance-check/validate.py` 报 `任务计划缺少章节`（验收条件/实施清单/证据/状态历史）。
  2. 修复后二次运行仍失败：`validate_bundle.py` 报 `发现旧项目版本引用`（recheck 文件中出现"无旧版本号引用"的**否定转述**也被命中）；`governance validate.py` 报 `DONE 任务仍有未勾选项: PLAN-20260814-010`（计划正文以 `[ ]` 字面量**转述其他文档**的历史勾选状态）。
- 上下文：M0-M7 文档对账任务创建 retrospective plan/recheck 文档；Windows PowerShell；bundle 与 governance validator 是 CI 门禁。
- 影响：两类 validator 红灯，阻塞交付；第二次失败的根因（字面量转述）与首次完全不同，容易误判为"还没改完"。

## Solution

- 根因（确定性权威证据：validator 源码正则/检查逻辑）：
  1. `validate_bundle.py` 用 `old_version` 正则全仓扫描受支持后缀文件（仅豁免 `.cursor/plans/archive/` 与 RETIRED memory），**连"无旧版本号引用"这样的否定转述也会被正则命中**。
  2. `governance validate.py` 的 `check_plans_and_rechecks` 对 status=DONE 的计划检查 `"[ ]" in body`——**即使 `[ ]` 出现在描述其他文档历史的语句中**；同时要求 plan 正文含 4 个强制章节（`## 验收条件 / ## 实施清单 / ## 证据 / ## 状态历史`）。
- 解法：
  1. 受扫描文件（`.md/.mdc/.yaml/.yml/.json/.py/.txt`，非 archive、非 RETIRED memory）中不写入旧版本号字面量，一律用描述性措辞（如"早期 Bootstrap 版本"）。
  2. DONE 计划正文不以 `[ ]` 字面量转述历史勾选状态，改写为"该行勾选状态缺失/未勾选"等描述。
  3. 新建 plan 文件时必须含 4 个强制章节；DONE 前所有 checklist 必须勾选。
  4. 写完新文档立即重跑两个 validator 闭环，不要只跑一个。
- 被拒方案：修改 validator 正则或检查逻辑（仓库规则明确禁止为通过验证而改 validator）。

## Evidence

- source_refs：本会话两次 validator 失败输出与修复后 PASS（`validate_bundle.py` + `governance validate.py`，2026-08-14）；validator 源码中的 old_version 正则与 check_plans_and_rechecks 逻辑。
- 如何失效：validator 扫描规则调整（如豁免 recheck 目录、改为语义扫描）或 plan 模板变更时本条不再适用。
