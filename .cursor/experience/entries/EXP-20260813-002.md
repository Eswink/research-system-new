# Windows 下 pytest 子进程找不到 venv Scripts 可执行文件（import-linter）时注入 PATH

## Problem

- 现象：`pytest tests/architecture -q` 报 7 项失败，全部为 `RuntimeError: lint-imports executable is unavailable in the frozen uv environment`（`shutil.which("lint-imports")` 返回 None）。
- 上下文：架构边界测试用 `shutil.which` 查找 `lint-imports` 再 subprocess 执行；直接运行 `d:\research-system\.venv\Scripts\lint-imports.exe --config .importlinter.domain` 是成功的。
- 影响：架构依赖边界门禁（Domain 纯度、relay 边界、fakes 无 provider 依赖）误报红灯，两次独立运行均失败。

## Solution

- 根因：pytest 子进程继承的 PATH 不含 venv `Scripts` 目录（IDE 终端启动时 venv 未激活）；`which` 找不到可执行文件，而非 import-linter 本身缺失。M6 会话 2 次观察 + M7 会话 1 次独立复现（跨会话，已触发 capture-learning）。
- 解法（首选）：`uv run --frozen --no-sync python -B -m pytest tests/architecture/python`——本会话 9 passed 实证，与 CI（`.github/workflows/m0-quality.yml`）完全一致，不依赖 shell PATH。
- 解法（备选）：运行 pytest 前显式注入 venv Scripts 到 PATH：

  ```powershell
  $env:PATH = "d:\research-system\.venv\Scripts;" + $env:PATH
  & d:\research-system\.venv\Scripts\python.exe -B -m pytest tests/architecture -q
  ```

  注入后 8 passed（M6 会话实证）。
- 被拒方案：直接改测试脚本跳过 `which` 检查（掩盖环境问题）；在 `pyproject.toml` 加 PATH 假设（跨平台不成立）。

## Evidence

- source_refs：注入 PATH 前后同一测试命令的 7 failed → 8 passed 对比（本会话终端输出）。
- 如何失效：CI/Linux 环境 venv bin 已在 PATH、或测试改用 `python -m import_linter` 入口时本条不再适用。
