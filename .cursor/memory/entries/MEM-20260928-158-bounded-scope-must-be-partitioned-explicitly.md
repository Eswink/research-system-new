## 做了什么

`tools/` 不在 `PRODUCT_ROOTS` 里 ⇒ 落在 `tools/` 的脚本不被 ruff / mypy / 规模门覆盖
（`tools/` 既有 `ruff check` **73 条**错误、`ruff format --check` **10 个文件**待重排，
逐个改造等于逼改历史资产）。GOAL-023 EC-02 的授权不允许改 `PRODUCT_ROOTS`，
于是新增判据 `tests/tooling/test_tooling_scripts_meet_product_gates.py`，
对**有界射程**执行与产品同款的四道门，做法是：

1. **射程 = 判据源码里的必备清单 ∪ 规范页点名的文件**（两处都算，源码提供下界，避免改文案绕过）；
2. 射程**之外**的候选对象以「**清单 + 理由**」逐条登记（本轮 37 条）；
3. 断言「**每个候选对象恰好落在射程内或登记在案**」——
   `tools/` 下 39 个 `.py` = 2 + 37，**没有第三种状态**；
4. 同时断言清单**不陈旧**（引用了不存在的文件即判红）与**理由非空**。

## 为什么这样做

「有界射程」的判据有一个不显眼的失效模式：它只断言**射程内**的东西。
于是**把一个新对象放进射程**这一步，成了判据完全看不见的动作 ——
新增一个 `tools/` 脚本时，最省事的做法是**什么都不做**，而「什么都不做」的效果
恰好是「让它不受任何检查」。判据因此会**随着时间推移变得更弱**，且**没有任何信号**。

把「射程外」也变成**必须显式写下来**的东西，失效模式就从「静默逃逸」变成
「**必须写一行理由**」。这不是对抗性控制（写一行理由仍然可以通过），
但它把**决定**从「默认不发生」变成「**必须被做出并被记录**」——
对「我不想改历史资产」这类**有意为之**的边界，这正是恰当强度的形式。

## 怎么做与复现

1. 先实测存量：`ruff check <目录>` / `ruff format --check <目录>` 拿到真实规模
   （本轮 73 条 / 10 个文件 ⇒ 证明「整目录扫」不可行）。
2. 用 `os.walk(<目录>, followlinks=False)` 取候选清单（**不**用 `rglob`：
   悬空符号链接会让它直接抛错）；跳过 `__pycache__`。
3. 判据的断言写成**分区**而不是**包含**：
   `未分类 = 候选 − 射程 − 登记` 必须为空；`射程 ∩ 登记` 必须为空；
   `(射程 ∪ 登记) − 候选` 必须为空（陈旧清单同样判红）；**且每条登记都有非空理由**。
4. 再加一条**下界**断言：必备清单必须含判据自己声明的关键对象
   （本轮 = 入口 + 断言集），防止有人把 `IN_SCOPE` 清空后仍判绿。
5. 按压形态：**新增一个未分类的脚本** ⇒ 判红；把它登记进「射程外」⇒ 转绿
   （这一步是**显式决定**，不是绕过）。

复现观察（GOAL-023 EC-02 实测）：`tools/` 候选 **39**；射程内 **2**；登记在案 **37**；
未分类 **0**。射程内四道门全绿（含 `ruff check` 的 `max-complexity = 10` 与行宽 100）。

## 适用边界

- 适用于**任何「目录太大、但又不该整目录纳入」的受判面**：`tools/`、`examples/`、探针目录、
  外部适配器、生成代码目录。
- **不适用于**「整目录都该受判」的场景（那时正确的做法是改根清单，而不是加分区判据）；
  也不适用于对象会**高速增长**的场景（每次新增都要改判据源码，维护成本随对象数线性上升）。
- 分区只保证「决定被显式做出」；它**不保证**决定是**对的**。有人可以把每个新脚本都登记为
  「历史遗留」——判据照绿。**不得**据此宣称覆盖面完整。
- 与 `MEM-20260925-141` 的分工：那条要求「射程不能只从文档取」；本条要求
  「射程外的部分也必须被枚举」。两条一起，射程才既有**下界**（源码）又有**封闭性**（分区）。
