## 做了什么

GOAL-023 EC-02 的受判射程是**并集**：

```text
射程 = 判据源码里固化的必备清单（IN_SCOPE） ∪ 规范页点名的 tools/**.py
```

EC-04 的按压 **P3** 把本轮新增的收口验证器从**必备清单**里撤掉，观察两面：

- 收口验证器的 `ec02-scope-pins-the-three-scripts` ⇒ **判红**
  （`必备清单缺少 ['tools/verify_goal023_closeout.py']`）；
- **EC-02 判据自己**（同一件事的另一面：分区判据 / 规模门 / 格式门 / 类型门）⇒ **`8 passed`，全绿**。

原因是该脚本**同时**被规范页点名（作为「标准收口断言集」的参考实现）⇒ 并集把它留在了射程里，
于是「必备清单少了一条」这件事，**在门判据的观察面上根本不存在**。

## 为什么这样做（为什么值得记）

「射程 = A ∪ B」这种写法**读起来**像是给射程加了下界（A 固定 + B 推导），
但在**失效语义**上它只保证了并集本身：**任何一侧收缩都可以被另一侧掩盖**。
本轮的实测形态尤其隐蔽 —— 被撤掉的那一条**仍然在射程内**，
所以「脚本是否受判」这个结论**没变**；变的是「**下界是否被声明**」。
这正是 `MEM-20260927-153`（每条声明的路都要有自己的证据）的同族问题：
**声明（下界）与推导（并集）是两件事，不能用一个判据同时代表。**

⇒ 结论：**并集型射程必须额外有一条「下界断言」**，且该断言要能**独立判红**；
否则「必备清单」只是注释，不是判据。

## 怎么做与复现

1. 把**必备清单**写在判据源码里（不写文档里），并**单独**断言它：
   `missing = [item for item in REQUIRED if item not in pinned]` ⇒ 非空即红，且**报出缺了谁**。
2. 断言「推导出的射程**吞掉**了必备清单」是**第二条**断言
   （`set(IN_SCOPE) <= set(scope())`）—— 它防的是**实现 bug**，**不是**清单收缩，两者不可互相替代。
3. 按压时**分别在两侧按**：从必备清单撤一条（应只在「下界断言」上红）、
   从文档撤一条（应只在「点名存在性」上红）。两次都记录**红在哪几条**。
4. 若两侧按同一条脚本，**并集不变 ⇒ 门类判据不会红** —— 这不是判据坏了，
   而是「**这个门看不见这件事**」；如实把它写进记录的 `W`，不要为了让两侧都红而改判据。

复现观察（GOAL-023 EC-04 实测）：P3 状态下验证器 `32 PASS / 1 FAIL`、`EXIT=1`；
EC-02 判据 `8 passed`；复原 raw `sha256` = `34d51ec9…` ⇒ `git diff` **空**、验证器 **33/33** 复绿。

## 适用边界

- 适用于**任何并集 / 推导型射程**：受判集合、扫描面、白名单、grep 面、CI 触发面。
- **不适用于**「唯一来源」的射程（此时并集本身就是下界，没有可收缩的第二侧）。
- 本条保证的是「**下界被显式声明**」。它**不**保证清单**内容完整**、
  也**不**保证文档点名的那一侧不会漂移（那一侧由「点名必存在」的断言覆盖）。
- 撤掉一条**同时**被两侧覆盖的对象时，**射程不变**是**正确**行为；
  把它读成「判据失效」会诱导你去改判据 —— 那才是真错。
