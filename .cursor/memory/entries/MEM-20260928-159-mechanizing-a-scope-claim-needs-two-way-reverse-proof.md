## 做了什么

GOAL-022 留了一句散文式范围声明（`RECHECK-20260928-218` 的 `W-1`）：
「EC-02 判据的受判起点 = 2026-09-28，**四条历史收口复检在射程外**」。
GOAL-023 EC-03 把它做成机械事实：新判据断言**射程外清单恰好是那四个文件名**、
**射程内计数 ≥ 1**、两集**互斥**，并给**两个方向**各配一条反证：

- **① 扩张方向**（backdate 逃逸）：把一条**新**记录的回填到起点之前 ⇒ 射程外会**多**一条 ⇒ 判红；
- **② 收缩方向**（回填历史）：把一条**历史**记录改成在射程内 ⇒ 射程外会**少**一条 ⇒ 判红。

两向都在 `tmp_path` 夹具与**真实记录**上各跑一次（真实记录那次用 Edit 按压、`raw sha256`
逐字节复原）。

## 为什么这样做

「射程外清单 = 这四条」这类断言，写法上很自然会被写成**单向包含**：
例如只断言「这四条**不在**射程内」。那条断言**能**防住「有人把它们拉进射程」，
但**完全看不见**「有人往射程外又塞了一条」（backdate 逃逸）——
而后者恰恰是**更可能的**失效形态：新记录只要写个更早的日期，就自动落到射程外，
**没有任何东西会说话**。

反过来，只断言「射程外的**每一条**都在登记清单里」也**不够**：
它防住了 backdate，但**看不见**「四条里的某一条被拉进了射程」（回填历史），
因为那只是让集合**变小**。

⇒ **集合相等**（既不多也不少）才是与「边界」这个谓词对齐的形态；
而**按压必须覆盖两个方向**，否则「判据被按压过」这句话只对了一半。
这与 `MEM-20260928-157`（按压要覆盖整节的所有出现）是同一族问题的两个面：
**按压的强度必须与被断言谓词的量词 / 方向对齐**。

## 怎么做与复现

1. 写出边界事实的**两个集合**（射程内 / 射程外）与它们的**期望值**（写死在判据源码里）。
2. 断言形式选**对称差为空**，不要选**单向包含**：
   `射程外 == 期望`、`射程内 >= 下界`、`射程内 ∩ 射程外 == []`。
3. 再加一条**扫描面两侧都非空**的断言 —— 任一边为空时，上面的等式退化成空转。
4. **两个方向各按一次**，并各自记录**红的是哪几条断言**：
   - 扩张：给某个在射程内的对象写一个「更早」的日期 ⇒ 期望它落进射程外；
   - 收缩：给某个在射程外的对象写一个「够晚」的日期 ⇒ 期望它离开射程外。
5. 复原用 `raw sha256` 复核逐字节（**不得**用 `git diff`：`.gitattributes` 归一化会掩掉行尾差异）。
6. 把边界事实写进判据源码时，**优先读既有判据的公开面**（阈值 / 前缀 / 谓词）而不是重抄一遍 ——
   这样既有判据的阈值漂移会让新判据判红（本轮的 `test_the_existing_judge_still_pins_the_boundary_constants`）。

复现观察（GOAL-023 EC-03 实测）：扫描面 5 / 射程内 1 / 射程外 4；扩张向按压 ⇒ `2 failed, 4 passed`；
收缩向按压 ⇒ `1 failed, 5 passed`；两次复原后合跑 **15 passed**。

## 适用边界

- 适用于**任何「集合边界」型断言**：受判集合、白名单、豁免清单、射程外登记、扫描面。
- **不适用于**「本来就只该单向」的断言：例如「这些文件必须存在」（不存在就是红，多出来无妨）。
  强行两向会把无关扩张也判红。
- 本条保证的是「**声明的**边界不会静默改变」。它**不**保证边界**本身**正确，
  也**不**校验声明字段（如 `created_at`）的**真实性** —— 回填是「写下另一个日期」，
  是过程纪律问题，不是对抗性控制。
- 若边界事实的期望值是**实测快照**（本轮即如此），它会把后续变化判红并要求**显式更新**；
  这**不**等于「所有历史对象已被穷尽识别」（不在扫描面里的对象本判据看不见）。
