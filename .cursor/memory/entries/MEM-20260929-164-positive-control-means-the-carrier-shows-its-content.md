## 做了什么

GOAL-025 cycle 2 给 GOAL-024 读面清单里**没有正控制**的 6 条声明载体（模板 ×2 / 记忆 /
交付物 / 库 ×2）逐条建了正控制，把 3 条**取不到**的路由判定化（1 条建成可取到、2 条断言
产品的 503 守卫），并把 4 个「无注入面」金丝雀源从散文式「未验证」收窄为**结构化断言**。

## 为什么这样做（为什么值得记）

- **「取得到响应」不是正控制**：GOAL-024 的清单对那 6 条载体只要求「路由取得到响应」
  （`kinds` 为空）⇒ 载体形同未验证：一条**永远返回 200 空体**的路由也能过关。
  正控制的定义是「**看得见它声明承载的内容**」：本次给每条载体注入合成金丝雀并断言真的看到。
- **`skip` 不是红**：取不到的路由如果 skip 掉，判据会绿着放过一个从未被观测的面。
  正确形态二选一：**能建的建成可取到**（本轮 `/library/{resource_id}` 经产品写面建条目后
  真的可取到），**不能建的断言产品的守卫**（workspace 快照：离线装配
  `deps.workspace_snapshots is None` ⇒ **真跑**这条路由实测 **503**，而不是跳过）。
  这条把「未验证」变成「结构性拒绝 + 具体守卫」。
- **必做面必须从既有登记推出 + 带下界**：如果正控制清单是**另写一份**，它会与登记面漂移，
  且可以靠「把一条正控制改判成机械理由」悄悄收缩必做面。所以必做集合要从既有登记
  **推出**（清单里 `kinds` 为空的行 ∪ 取不到集合），再加一条**下界**断言；
  按压「降级一条正控制」必须判红。
- **正控制要反证「注入真的生效」**：只证明「注入后看得到内容」还不够 ——
  可能原现场本来就有内容。必须同时断言「**不加注入**时看不到」，
  否则正控制可能与既有事实混淆。

## 怎么做与复现

1. **必做面**：从既有登记推出（`kinds` 为空的声明行 ∪ 取不到集合），与矩阵比对；矩阵行理由非空。
2. **注入**（一律合成串，且**不改被复用的参考资产**）：模板用**换入的模板目录实例**
   （子类提供 `yaml_text`），记忆 / 库条目走**产品自己的写面**（`POST /memory/proposals`、
   `POST /projects/{id}/library`），交付物 seed 与产品 `_artifact_ref` **同形**的制品 id。
3. **守卫**：取不到的路由**真跑**并断言守卫状态码（503）+ 断言守卫的**前置事实**
   （`deps.workspace_snapshots is None`）⇒ 前置一变，理由失效并判红。
4. **下界 + 按压**：`MIN_POSITIVE_CARRIERS` 写死在源码里；按压「抽空理由 / 抬下界 /
   降级一条正控制」三处都要先红后绿，raw `sha256` 逐字节复原。
5. **两向反证**：不加注入时看不到内容（正控制是注入造成的）；载体看不到声明内容 ⇒ 判红点名。

## 适用边界

- 正控制证明的是**出口能力**（route-level）：模板走的是换入实例，**不是**产品内置目录里的真实模板。
- 「无注入面」的机械证据里，`tool_arguments` / `tool_output` 是**属性面断言**
  （Fake 上无工具调用面）+ 「枚举里确有该 kind」；**不**证明真实工具面启用后的行为。
- `task_input` 的断言落在**显式列举的字段**上 ⇒ 将来新增自由文本字段**不会自动判红**，需人工同步。
- 只对**默认离线链**成立；真实 runtime / 工具面 / 部署面（配置了快照根）未验证。
- **不构成**任何"项目安全"结论（`R-M1` 未收口）。
